# Veridis Lite · 词汇净化精简版

基于 [Veridis Rewrite](https://github.com/The-Veridis-Lion/Veridis-Rewrite) 制作的非商业精简改版。原作者：[The-Veridis-Lion / Veridis](https://github.com/The-Veridis-Lion)；原项目 [Discord](https://discord.com/channels/1134557553011998840/1488671923776000020)。

只保留一页规则管理：预设的新建、切换、重命名、导入、导出、删除；规则分组的添加、启停、复制、搜索、排序；普通文本、简易组合和正则表达式三种匹配方式。

回复完成后执行本地替换或删除，不调用模型，不需要酒馆助手。没有 AI 配置、改写要求、Deep Clean、数据库联动、透视记录、匿名反馈或自动更新功能。

## 安装

安装最新版时，在 SillyTavern 的扩展菜单中选择「安装扩展」，粘贴本仓库地址。

也可以从仓库的 Releases 页面下载指定版本的 `Veridis-Lite-1.0.0.zip`，按下面的步骤手动安装。

1. 解压安装包，将 `Veridis-Lite` 文件夹放进酒馆现有的第三方扩展目录，与原版扩展文件夹同级。常见全局目录为 `public/scripts/extensions/third-party/`。应直接得到 `Veridis-Lite/manifest.json`，不要多套一层同名目录。
2. 在酒馆扩展管理中关闭原版 Veridis Rewrite，再刷新页面并启用精简版，避免两套替换同时执行。
3. 从魔法棒菜单或扩展设置中的“词汇净化 · 精简版”进入。
4. 首次打开时，预设和规则列表为空。选择「新建」创建自己的预设，再添加规则组和规则，也可以选择「导入」加载你自己的预设 JSON。修改会自动保存。

这是普通的 SillyTavern 前端扩展。使用时无需 Node 开发环境、`npm install`、编译或额外服务。远程酒馆需要把文件放到远程酒馆的扩展目录。

## 规则填写

- **普通文本**：匹配内容按原样匹配，每行一项，保留标点和空格。替换内容留空即删除；多行替换候选会在每次命中时随机选一个。
- **简易组合**：`{非常,极其}` 表示二选一；`*` 匹配最多 15 个字符，且不跨句末标点或换行。例如 `{非常,极其}*认真` 可统一替换为 `认真`。
- **正则表达式**：支持裸表达式和 `/表达式/flags`。例如 `编号(\d+)` 替换为 `$1`；支持 `$1` 至 `$99` 捕获组及 `\n`、`\r`、`\t`。非法表达式会显示错误，匹配空字符串的规则会被拒绝或跳过。
- **备注**只供自己查看和搜索，不参与匹配。

普通文本沿用上游的最长目标优先、相同目标靠后规则优先的逻辑；普通文本替换后，再按分组顺序执行简易和正则规则。规则可能相互影响，导入后可先用一条新回复确认结果。

## 与原版预设的关系

支持原版的规则数组、`rules`、`__content__` 和 `content` 等常见 JSON 包装。普通规则、分组启停状态、替换候选和备注会保留。旧版 AI 规则会跳过，导入成功时显示跳过数量；只含 AI 规则的文件会拒绝导入。导入失败不影响现有预设。

精简版使用独立设置 `veridis_lite`。旧版的 AI 接口、Key、提示词、绑定与历史记录均不导入，也不出现在导出文件里。没有自动读取或迁移旧插件设置的启动行为。

## 自动处理的范围

- 处理新生成、重新生成和新 Swipe 的助手回复，并同步当前 Swipe 的正文。
- 继续生成时，仅处理可精确确认的追加部分，避免把已经替换过的前文再替换一次；追加边界发生变化时跳过并提示。
- 不自动重处理旧聊天、切回的旧 Swipe、用户消息、系统消息或角色预设开场白。
- 固定保护 `<UpdateVariable>…</UpdateVariable>`（包括未闭合块的后续内容）和 `<StatusPlaceHolderImpl/>`，避免规则改动 MVU 数据。没有额外的范围设置页。
- 不修改生成过程中的显示，不保存原文或差异历史。聊天、消息或 Swipe 已切换时拒绝旧任务写回；没有变化时不额外保存聊天。

## 验证

克隆源码仓库后，运行以下命令验证核心功能。

```sh
npm test
```

这是规则引擎、旧预设导入以及模拟酒馆生命周期的离线测试。浏览器检查使用真实扩展入口和界面、模拟宿主和保存接口，运行时不调用真实模型，也不启动 HTTP 服务：

```sh
npm install
npx playwright install chromium
npm run test:ui
```

可选环境变量 `VRL_TEST_CHROME` 指向现有 Chrome/Chromium 程序，`VRL_TEST_MODULES` 指向含 Playwright 的外部 `node_modules` 目录。PowerShell 使用 `$env:VRL_TEST_CHROME='完整路径'` 的写法。界面检查输出到 `test-results/`。
